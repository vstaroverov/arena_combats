# ЯРОСТЬ — сборка для развёртывания

Готовая игра находится в **dist/**. Сборка и установка npm-зависимостей не нужны. Фавиконы и SEO-метаданные включены. Данные владельца прежнего хостинга, `.git`, `.openai` и ключи доступа в комплект не входят.

## Быстрый запуск

Нужен Node.js 24 или новее. Проверенная версия при подготовке: 24.20.0.

Открой терминал **в этой папке** и выполни:

```sh
npm start
```

Открой http://127.0.0.1:4173. Проверки: `npm test`.

## Развёртывание на сайте

Предпочтителен Node-хостинг или VPS: сервер раздаёт статику и обслуживает реальные счётчики зрителей.

1. Загрузи эту папку на сервер. Установи Node.js 24+.
2. Задай переменные окружения: `PORT` — внутренний порт приложения, `HOST` — адрес привязки, `PUBLIC_ORIGIN` — точный публичный адрес, например `https://game.example.com`, без пути. Подставь настоящий домен.
3. Запусти `node server.mjs` через менеджер процессов хостинга с автоматическим перезапуском.
4. Направь HTTPS-домен через reverse proxy на порт приложения. Проксировать нужно **и /**, **и /api/presence**. Не заменять POST на GET и не кэшировать `/api/`.
5. Проверь главную, фавикон, покупку поддержки игровым балансом, ставки, сохранение после перезагрузки и счётчики зрителей. У нескольких вкладок одного браузера один зритель.

Пример Linux за reverse proxy:

```sh
HOST=127.0.0.1 PORT=3000 PUBLIC_ORIGIN=https://game.example.com node server.mjs
```

Пример PowerShell:

```powershell
$env:HOST = '127.0.0.1'
$env:PORT = '3000'
$env:PUBLIC_ORIGIN = 'https://game.example.com'
node server.mjs
```

Для контейнеров обычно требуется `HOST=0.0.0.0`. Включён Dockerfile:

```sh
docker build -t yarost .
docker run -d --name yarost --restart unless-stopped -p 127.0.0.1:3000:3000 -e PUBLIC_ORIGIN=https://game.example.com yarost
```

Docker-образ здесь не собирался; проверялся непосредственный запуск Node-сервера.

Можно скопировать `.env.example` в `.env`, заменить домен и запустить `node --env-file=.env server.mjs`. Обычный `npm start` сам `.env` не загружает.

### Если хостинг поддерживает только статические файлы

Публикуй содержимое **dist/** в корне сайта. Игра запустится, но API зрителей будет отсутствовать: счётчики покажут «—». Для них нужно отдельно реализовать совместимый обработчик `/api/presence`. `robots.txt` и иконки также должны быть доступны из корня сайта.

## Что важно знать перед передачей

- Игровой мир, турниры, бойцы, лайки, монеты и ставки сейчас хранятся в **localStorage конкретного браузера**. Симуляция идёт, пока открыта вкладка. Это не общая круглосуточная серверная лига.
- Игровые средства виртуальные; пополнение бесплатное, реальных платежей и вывода нет. Клиентские расчёты нельзя использовать для денежных операций.
- Node-сервер хранит только присутствие зрителей в памяти. Счётчики сбрасываются при перезапуске. Для нескольких экземпляров сервера нужен общий store; сейчас запускать один экземпляр.
- Прогресс со старого localhost **не перенесётся автоматически на другой домен**: localStorage привязан к origin. Данные не включены в эту сборку.
- Общие аккаунты, база данных, серверная симуляция, общие лайки и реальные платежи — отдельная будущая разработка, не часть развёртывания этой папки.
- Шрифты загружаются с Google Fonts; предусмотрены системные запасные. Флаги и иконки находятся локально.

## Содержимое

| Путь | Назначение |
| --- | --- |
| `dist/` | Готовая статика и игровые модули |
| `server.mjs`, `presence.mjs` | HTTP-сервер и счётчики зрителей |
| `test/` | Проверки логики игры |
| `scripts/` | Генерация иконок и обновление справочников |
| `SEO_CORE.md` | Семантическое ядро и задачи для публичного домена |
| `FLAG_SOURCES.md`, `CITY_SOURCES.md` | Источники изображений и справочников |
| `GAME_IDEA.md`, `DEVELOPMENT.md` | Концепция и история реализованных возможностей |
| `HANDOFF_PROMPT.txt` | Готовое сообщение для другого чата |

## SEO после выбора домена

В `dist/index.html` уже есть title, description, Open Graph, Twitter-метаданные, VideoGame JSON-LD и один H1. Canonical, og:url, абсолютные URL изображений и sitemap.xml добавляются **после выбора реального публичного HTTPS-домена**. Не использовать localhost и не возвращать старое название UFC. Полный список задач — в `SEO_CORE.md`.
