# Тестовая ЮKassa на arena.v-star-group.ru — обновление 2.3.1

Задача для развёртывания: обновить существующий сайт с версии 2.2.0, сохранить общий мир и профили, включить только тестовые платежи. При подготовке обновления магазин принял ключ и создал тестовый заказ на 100 ₽; оплата и webhook ещё не проверены.

## Обновление

1. Прочитать DEPLOYMENT.md и PAYMENTS.md. Определить действующий процесс, постоянный WORLD_DB, окружение и reverse proxy. Не создавать второй процесс для той же базы.
2. Сделать согласованную резервную копию действующей базы командой `npm run backup` с тем же WORLD_DB. Затем остановить процесс и заменить код всем содержимым сборки, сохранив базу и серверные секреты. Не загружать только dist/.
3. Сохранить прежние WORLD_DB, HOST, PORT и TRUST_PROXY. Не копировать локальную базу разработчика. При старте схема 2 автоматически мигрирует в 3 с сохранением мира, GUID и бесплатных балансов. Старый код со схемой 2 больше не открывать на этой базе.
4. Добавить в окружение сервера следующие настройки:

```dotenv
PUBLIC_ORIGIN=https://arena.v-star-group.ru
YOOKASSA_ENABLED=1
YOOKASSA_MODE=test
YOOKASSA_SHOP_ID=1509255
YOOKASSA_SECRET_KEY=REPLACE_WITH_TEST_SECRET_FROM_OWNER
YOOKASSA_RECEIPT_MODE=test_no_receipt
YOOKASSA_EXTERNAL_RECEIPTS_CONFIRMED=0
```

Заглушку ключа заменить на предоставленный владельцем тестовый секрет через защищённую настройку окружения. Не размещать его в репозитории, браузерном коде или отчётах. Локальная копия у разработчика находится в игнорируемом `github/arena_combats/.env` и не включена в архив. Не переносить этот файл целиком: там указан отдельный локальный тестовый WORLD_DB, который нельзя использовать вместо базы работающего сайта.

Если используются `.env`, процесс запускать `node --env-file=.env server.mjs`: обычный `npm start` файл не читает. Существующие переменные процесса имеют приоритет над `.env`; проверить значения без вывода ключа.

В сборке также есть готовый файл `yookassa-test.env.example` с доменом и настройками тестового магазина, без секрета и без изменения пути базы. Его можно использовать при запуске:

```sh
node --env-file-if-exists=.env --env-file=yookassa-test.env.example server.mjs
```

Секрет `YOOKASSA_SECRET_KEY` должен быть задан в серверном окружении или существующем защищённом `.env`. Сохранить действующий WORLD_DB. Если в окружении процесса уже заданы YOOKASSA_MODE, YOOKASSA_SHOP_ID или другие платёжные переменные, привести их к тестовым значениям выше: они имеют приоритет над файлами. Без ключа платежи не включатся. Боевой ShopID 1508290 в этой сборке не используется.

5. Перезапустить один процесс Node.js 24+. Проверить `/api/health`: версия 2.3.1, ok=true, затем catchingUp=false. Проверить прежний GUID, бойцов и бесплатные балансы.

## Уведомления и проверка

В кабинете именно тестового магазина настроить HTTP-уведомления:

```text
https://arena.v-star-group.ru/api/payments/webhook
```

События: `payment.succeeded`, `payment.canceled`, `refund.succeeded`. Прокси должен передавать POST на Node без кэширования и авторизации. Для test_no_receipt не включать обязательную проверку чеков в тестовом кабинете. Настоящие налоговые настройки этим режимом не заменяются.

Войти на сайт, сохранить GUID, открыть «+» платного баланса и создать новый тестовый платёж. Использовать только [тестовые способы оплаты ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing). Завершить оплату, проверить возврат на сайт и зачисление в отдельный тестовый баланс. Повторное уведомление/проверка не должны начислять средства второй раз. Проверить отмену и тестовый возврат. Тестовые средства не оплачивают поддержку и создание бойцов, бесплатные пари остаются отдельно.

Не использовать созданный разработчиком заказ для проверки сайта: он относится к отдельной локальной базе и не зачислится в профиль публичного сайта. Проверку проводить новым заказом из профиля на сайте.

После установки сообщить версию, результаты проверки оплаты/повторного уведомления и сохранения мира. Реальные платежи не включать: для них потребуются боевой магазин и подтверждённые настройки чеков из PAYMENTS.md.
