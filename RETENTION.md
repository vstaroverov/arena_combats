# Хранение и автоматическая очистка

С версии 2.2.0 сервер чистит временные данные при запуске и после московской полуночи. Переход даты проверяется раз в минуту. При остановленном сервере пропущенная очистка выполняется при следующем запуске.

| Данные | Что остаётся |
| --- | --- |
| Текущий бой | Последние 50 событий; старые хроники остальных турниров очищаются |
| Последние результаты | 30 боёв и 20 чемпионов |
| Операции казны и бойцов | По 40 последних записей; накопительные суммы сохраняются |
| Награды бойца | 50 последних наград и общий счётчик за карьеру |
| Завершённые ставки | Не старше 30 дней, максимум 100 на профиль |
| Открытые ставки | До расчёта, независимо от возраста; максимум 500 новых открытых ставок на профиль |
| Удалённая история ставок | Суммарные количество, суммы ставок и выплат, число побед/поражений/возвратов |
| Квитанции повторных действий | До 7 дней и максимум 200 на профиль |
| Сессии | До истечения годового срока cookie |
| Отозванные сессионные токены | 7 дней после смены профиля |
| Блокировки входа по GUID | До истечения 24 часов, затем удаляются при очистке |
| Пустые неактивные профили | После 30 дней из снимка удаляется только пустой кошелёк; GUID сохраняется |
| Отчёт очистки | Одна последняя запись в таблице `maintenance`, без накопления журналов |

Ограничения числа записей применяются также при новых действиях и расчёте боёв, поэтому история не растёт без ограничения между ежедневными очистками. Сроки удаляются при ближайшей ежедневной очистке или обработке соответствующего профиля. Старые квитанции без времени получают семь дней с момента обновления.

## Что не удаляется

GUID-коды, реальные значения игровых балансов, бойцы, владение ими, поддержка, навыки, рейтинг, общая статистика и активные турнирные сетки сохраняются. Очистка истории ставок не начисляет и не списывает деньги повторно.

Пустой профиль — исходный баланс 15 000, без ставок, лайков, квитанций, пополнений, архива ставок и собственных бойцов. При возвращении по cookie или GUID его пустой кошелёк восстанавливается с теми же исходными 15 000. Профили с прогрессом не удаляются. Последнее посещение учитывается на сервере с точностью до 15 минут.

Личное меню показывает только недавнюю историю ставок; её свёрнутые итоги хранятся отдельно. Архив не содержит полных старых купонов и не предназначен для финансового или юридического аудита реальных платежей. Все средства игры виртуальные.

## Размер SQLite

Удалённые страницы SQLite используются повторно. WAL автоматически проходит checkpoint примерно через 1000 страниц; `journal_size_limit` настроен на 8 МиБ. Это целевой размер неактивного журнала, а не абсолютный предел: активный читатель может временно удерживать WAL.

Ежедневно выполняются checkpoint/TRUNCATE и optimize. При наличии не менее 8 МиБ свободных страниц и не менее 20% пустого файла выполняется VACUUM. Уплотнение проходит после транзакции очистки. При занятости базы эта необязательная операция откладывается, игра не останавливается из-за блокировки уплотнения. На большой базе VACUUM может занимать время; для него нужно свободное место на диске.

Рост полезных данных остаётся возможным: новые пользователи и созданные бойцы требуют места. GUID нельзя удалять ради жёсткого размера файла, сохраняя обещание входа по коду. Текущая архитектура одного SQLite-снимка рассчитана на небольшую лигу, а не на миллионы активных игроков.

## Резервные копии и внешние журналы

Сервер не создаёт бесконечную цепочку резервных копий и не пишет отдельный access log. Команда `npm run backup` создаёт копию по явному запуску и не удаляет предыдущие копии автоматически.

На хостинге отдельно настроить ротацию журналов Node/менеджера процессов/reverse proxy и резервных копий: эти файлы находятся вне игровой базы. Например, хранить семь дневных резервных копий, а внешние логи — не больше 14 дней с ограничением размера файлов. Конкретная настройка зависит от хостинга. Приватные GUID и cookie нельзя включать в логи.
